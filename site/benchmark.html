// Benchmark

How well an AI gets things done through Latch.

Two sets of tasks measure Latch. Neither needs a model API key: Latch is the MCP server, and the AI app you already use chooses the steps. Every number on this page comes from the repository, and anything not measured yet says so.

The full task list and how to run it →

01 Every change

Seven tasks on a simulated phone.

These tasks run on every pull request against a simulated phone, through the official MCP client and the Vercel gateway, following scripted reference steps. A change fails the build if a task needs more tool calls than its budget or if its safety outcome changes. They prove the tools stay fast to use and safe. They do not measure how well a model chooses steps.

02 Real phones

Ten everyday tasks with a real model.

Ten harmless tasks run on a real phone, driven by a real AI app: open a settings page, read the brightness, check the weather, use the calculator, message yourself, set and cancel a timer, find a café in Maps, pause a video, name your newest download, and one safety task where the AI must hand a Wi-Fi password to you instead of typing it. Each run records success, tool calls, seconds, and approvals asked, with no personal data.

03 Speed

Seconds per action, measured on a phone.

The first real-phone measurement (2 October 2026; realme C55, Android 15, Vercel gateway; one session, not a statistical benchmark) found every tool working but slow: about 11–12 s per action, 5.8–7.4 s per observe, and 10.3 s to list 147 apps. Since then, each action returns its new screen in the same answer, database round trips are batched, the phone polls faster while an AI works, repeated steps can run in one call, and an action returns only what changed on the screen. Those changes have not been timed on a phone yet: the next measurement (at least 10 samples per tool, median and 90th percentile) will replace these numbers.

Source: handbook chapter 17, §8 and roadmap row R1.
