// Security compared

Who can do what, and who sees your screen.

Phone automation tools are built for different jobs. Test-automation agents drive a phone you develop on, from a computer, over USB debugging. Latch is for your own personal phone, from any AI app, while you are away from your computer. That changes what has to be protected. This page compares the two approaches using each project's own documentation.

01 Side by side

Latch and an ADB test agent.

The example is Google's ARTEMIS, an open-source Android automation agent released in August 2026, as described on its GitHub page when this page was written (15 October 2026). "Not documented" means that page does not describe it, not that the project lacks it.

02 Honest limits

What Latch does not protect against.

  • Your AI app's provider sees what the AI sees. The model has to read a screen to act on it. Choose an AI app you would trust with that screen.

  • A cloud gateway sees screens in transit. Self-hosting the container gateway is the answer. Latch runs no servers of its own.

  • Spotting Send, Pay, and password fields is a safety net, not a guarantee. Latch uses Android's own signals first and word lists second. Turn on Ask me before every action for apps that matter.

  • Latch is in beta and has not had an outside security audit.
